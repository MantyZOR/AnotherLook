# Временная замена Explorer

Экспериментальный режим запускается вручную: **Настройки → Режим рабочего стола → Работать вместо Explorer сейчас**. Его также можно запросить параметром `--replace-explorer`. Обычный запуск сохраняет прежний режим поверх Windows.

Замена действует только в текущем сеансе. Программа не меняет Winlogon, Custom User Interface, Shell Launcher, системные политики клавиатуры или настройки UAC. После следующего обычного входа Windows запускает свою прежнюю оболочку.

Перед переключением заверши копирование файлов в Проводнике. При штатном завершении Explorer его окна папок могут закрыться. Другие приложения намеренно не закрываются.

## Переключение и возврат

1. Another Look проверяет свои поверхности и независимого помощника восстановления. Приёмник значков трея подготавливается до остановки Explorer.
2. В профиле записывается `explorer-session.json`. Запись содержит версию формата, пользователя, сеанс, рабочий стол Windows, PID и время создания процесса оболочки Another Look. Без успешной записи Explorer не останавливается.
3. Restart Manager получает только PID и время создания выбранного процесса Explorer. Список затронутых процессов должен содержать ровно этот процесс. Принудительная остановка, завершение по одному имени EXE и регистрация всех пользователей файла `explorer.exe` не применяются.
4. Если Windows отказывает, Explorer не завершается или сразу возвращается, режим отменяется с попыткой восстановления обычного рабочего стола.
5. «Вернуться к рабочему столу Windows», завершение программы и аварийное сочетание возвращают Explorer. При обычном выходе интерфейс Another Look остаётся доступен, пока не подтверждено появление рабочего стола и панели Explorer.

Повторные запросы переключения не создают новые рабочие потоки. Остановка и возврат выполняются вне потока интерфейса. В активном режиме нет отдельного таймера постоянного поиска Explorer: его возвращение отслеживается существующими оконными событиями.

Другой экземпляр не может одновременно начать замену в том же сеансе Windows. Запуск с повышенными правами для этого режима отклоняется: оболочка и её Explorer должны работать с обычными правами пользователя.

## Восстановление после сбоя

Независимый помощник использует запись восстановления при завершении основного процесса. При ручном аварийном выходе он также записывает отмену, которую проверяет работающий поток переключения. Незавершённая запись проверяется при следующем запуске. Чужой пользователь, другой сеанс, другой рабочий стол и повреждённый формат не принимаются за разрешение на восстановление.

Если возврат не подтверждён, запись сохраняется для повторной попытки. Можно запустить тот же EXE с параметром `--recover --data "папка профиля"`. Для обычного интерфейса сохранено независимое сочетание **Ctrl + Alt + Shift + Space**. Через Диспетчер задач остаётся возможность вручную запустить системный `explorer.exe`.

## Ограничения

- Горячая смена оболочки не является атомарной операцией Windows. Короткая смена рабочего стола и поведения панелей во время перехода возможна.
- Запуск Проводника или некоторых системных компонентов может снова поднять оболочку Explorer. В таком случае Another Look отменяет замену и возвращает Windows, не пытаясь постоянно завершать Explorer. Совместимость файлового менеджера в этом режиме требует отдельного ручного прогона.
- Собственный трей сохраняет ранее импортированные классические значки и отправляет `TaskbarCreated`. Некоторые программы не пересоздают значок; действия, предоставленные только через UI Automation старого Explorer, после его завершения недоступны.
- Этот режим не превращает Another Look в замену DWM, не передаёт ему все системные сочетания и не снимает ограничения доступа к повышенным или защищённым окнам.
- Постоянный запуск вместо Explorer при входе в учётную запись в эту версию не включён.

## Что проверяется автоматически

`goodview_explorer_session_tests` проверяет транзакцию с внедрением отказов: запрет остановки, повторный запуск Explorer, ошибки записи, отмену во время остановки, неудачный возврат и повторную попытку, исключения, освобождение владельца и 1000 повторных запросов. Нативный Restart Manager проверяется на отдельном собственном тестовом процессе вне экранов. Настоящий Explorer эти тесты не останавливают.

Отдельный явно запускаемый `goodview_explorer_desktop_tests` создаёт невидимый рабочий стол через `CreateDesktop`, не вызывая `SwitchDesktop`. На нём запускается настоящий Explorer, проверяются его штатная остановка, возврат, аварийное завершение владельца транзакции и восстановление по оставленной записи. PID Explorer видимого рабочего стола защищён от остановки; после прогона также проверяются прежние HWND, PID и время создания этого процесса. Тестовый Explorer затем завершается, рабочий стол освобождается.

На Windows 10 Pro 22H2 этот прогон прошёл для 0.8.19. Проверка выявила, что назначенное Windows окно оболочки может иметь класс `MSTaskSwWClass`; проверка теперь учитывает `GetShellWindow` и подтверждает процесс, пользователя, сеанс и рабочий стол, а не полагается только на имя класса.

```powershell
cmake --build build/native --target goodview_explorer_desktop_tests
.\build\native\goodview_explorer_desktop_tests.exe --isolated-explorer .\test-artifacts\isolated-explorer
```

Этот прогон подтверждает нативную транзакцию и возврат настоящего Explorer. Он не заменяет ручную проверку видимого перехода, поведения сторонних приложений, трея и сочетаний на разных версиях Windows. Режим остаётся явно включаемым экспериментом.
