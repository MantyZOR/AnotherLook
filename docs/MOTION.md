# Появление окон и меню

В «Настройки → Движение интерфейса» меню и окна настраиваются отдельно. Та же кнопка есть в верхней части окна настройки интерфейса. Выбор сохраняется после перезапуска.

- **Созвездие:** сначала проявляются связи, затем карточки действий.
- **Лепестки:** карточки слегка расходятся от общего центра, без связей.
- **Чертёж в сборке:** появляется верхняя линия, затем раскрывается окно с содержимым.

Для меню и окон можно выбрать отсутствие движения. Отключение анимаций в Windows и удалённый сеанс тоже учитываются.

## Где работают эффекты

Общий вид меню используется в действиях карточек, добавлении виджетов, управлении окнами и других собственных меню. До 16 действий можно разместить отдельными карточками, если хватает места и бюджета памяти. Слишком длинные списки сохраняют обычную прокрутку; ради эффекта текст не уменьшается. Меню поддерживают клавиатуру, подменю и отмену через Escape.

Общее появление подключено к поиску, редакторам, настройкам расположения и оформления, настройкам индекса, выбору значка пространства, уведомлениям и отдельным веб-окнам приложения. Окна других программ не затрагиваются. Постоянные панели рабочего стола используют свои существующие эффекты.

## Расход ресурсов

Меню раскрывается за 280 мс, окно за 260 мс. Таймер с шагом 16 мс работает только во время перехода и затем удаляется. Скрытие и закрытие окна также останавливают переход. Повторное движение мыши внутри одного действия не вызывает нового кадра.

Текст и значки меню рисуются один раз. В кадре перемещаются готовые изображения; наведение добавляет лёгкую обводку без повторной подготовки текста. Общий кеш меню ограничен **6 МиБ** и освобождается при закрытии. Это ограничение изображений меню, а не всей памяти процесса.

Обычное окно раскрывается изменением видимой области. Положение окна и его полей не меняется. Снимки экрана, дополнительные прозрачные окна и полноразмерные копии диалогов для этого не создаются. По окончании восстанавливается исходная форма скруглений. Действие пользователя имеет приоритет над переходом.

## Контрольный замер 0.8.16

Скрытый программный рендерер на Intel Core i5-7500, семь действий, 96 DPI, прогретые изображения. Для появления выполнено 480 кадров, для наведения — 240. В двух коротких прогонах:

| Показатель | Значение |
| --- | ---: |
| CPU кадра появления | около 0,7–0,85 мс |
| CPU кадра наведения | около 0,52–0,78 мс |
| Кеш меню с семью действиями при 96 DPI | 1 168 080 байт, около 1,11 МиБ |
| Максимум в серии 96–192 DPI с кнопкой возврата | 5 355 648 байт, около 5,11 МиБ |

Это стоимость подготовки кадра, без его передачи DWM и без обещания конкретного процента CPU на живом рабочем столе. Подготовка шрифтов и изображений при открытии не входит в прогретую серию. Открытие требует кратковременной работы; постоянного цикла анимации после него нет.

Проверены три темы, масштабы 100, 125, 150 и 200%, прозрачность и premultiplied alpha, соответствие видимых действий областям нажатия, сохранение настроек, восстановление скруглений, закрытие и скрытие во время перехода, изменение размера и раннее действие пользователя. Тестовые окна находятся за пределами экранов и показываются без активации. Перехват ввода и переключение пользовательских окон не используются.

Отдельный сценарий:

```powershell
cmake --build build/native --target goodview_menu_motion_tests
ctest --test-dir build/native -R '^menu_and_window_opening_motion$' --output-on-failure
```

JSON и контрольные изображения остаются в `build/native/menu-motion/`. Методика проверки CPU обычной работающей оболочки описана в [LIVE_PERFORMANCE.md](LIVE_PERFORMANCE.md).
